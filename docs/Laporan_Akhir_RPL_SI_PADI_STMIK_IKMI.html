BAB I
PENDAHULUAN

1.1 Latar Belakang Inovasi Web Percobaan

Sektor pertanian padi merupakan tulang punggung ketahanan pangan nasional yang memiliki peran strategis bagi perekonomian masyarakat pedesaan. Di tengah laju transformasi digital era Revolusi Industri 4.0 dan Society 5.0, tata kelola agrikultur di tingkat desa pada umumnya masih mengandalkan pola tradisional dan pencatatan manual. Ketiadaan integrasi teknologi komputasi menyebabkan pemantauan luas baku lahan, penjadwalan pemupukan, rekapitulasi hasil panen, hingga deteksi dini serangan hama sering kali mengalami keterlambatan.

Sebagai inisiatif mandiri dalam menjawab tantangan tersebut, penulis merancang sebuah web percobaan dan purwarupa (prototype) sistem informasi pertanian digital dengan judul SI PADI: Sistem Informasi Pertanian & Manajemen Budidaya Padi Terintegrasi Artificial Intelligence dan Early Warning System. Objek percontohan (pilot project) yang dipilih dalam perancangan web percobaan ini adalah Desa Cirebon Girang, Kecamatan Talun, Kabupaten Cirebon, Jawa Barat.

Desa Cirebon Girang memiliki potensi agraris yang sangat nyata dengan hamparan sawah produktif seluas 6,00 Hektar (60.000 m²) yang terbagi ke dalam 4 petak lahan utama pada 3 dusun: Blok Manis (Dusun Karang Anyar), Blok Wage (Dusun Girang Hilir), dan Blok Pahing (Dusun Cirebon Ilir). Potensi lahan ini dikelola oleh 3 Kelompok Tani (Poktan) binaan desa, yaitu Poktan Sri Rejeki, Poktan Sumber Subur, dan Poktan Tani Makmur.

Melalui analisis umum terhadap kebutuhan manajerial pertanian desa, teridentifikasi sejumlah kendala mendasar yang ingin dipecahkan melalui web percobaan ini:

  1. Pencatatan Konvensional: Pendataan inventarisasi luas petak, kepemilikan lahan, dan registrasi anggota kelompok tani masih dicatat dalam buku kas fisik, sehingga rawan tercecer dan batas spasial petak sawah tidak terdokumentasi secara digital.
  2. Tantangan Jadwal Pemupukan Presisi: Petani sering kesulitan menghitung umur tanaman secara tepat berbasis Hari Setelah Tanam (HST), sehingga jadwal penaburan pupuk dasar, susulan I (10–14 HST), dan susulan II (30–35 HST) kerap terlambat diaplikasikan.
  3. Ketiadaan Peringatan Dini Instan: Saat terjadi perubahan anomali cuaca lokal atau ancaman serangan Organisme Pengganggu Tanaman (OPT) seperti wereng batang coklat, peringatan dari desa belum memiliki saluran komunikasi otomatis yang dapat langsung diterima oleh ponsel petani.
  4. Kebutuhan Konsultasi Cerdas & Pelaporan Kedinasan: Petani membutuhkan media konsultasi budidaya instan tanpa harus menunggu penyuluh, sementara pihak perangkat desa memerlukan rekapitulasi panen yang siap diekspor menjadi format laporan resmi ber-Kop Surat Dinas untuk diserahkan ke Dinas Pertanian.

Rancang bangun web percobaan SI PADI ini dikembangkan dengan harapan dan visi ke depan: siapa tahu purwarupa sistem ini kelak dapat benar-benar diuji coba secara nyata, bermanfaat luas, dan terpakai secara langsung oleh pihak pemerintah desa serta kelompok tani di Desa Cirebon Girang.

BAB II
LANDASAN TEORI

2.1 Rekayasa Perangkat Lunak & SDLC

Rekayasa Perangkat Lunak (Software Engineering) adalah penerapan pendekatan sistematis, disiplin, dan terukur terhadap pengembangan, pengoperasian, dan pemeliharaan perangkat lunak (IEEE Standard 610.12). Dalam proyek ini, metodologi yang diterapkan mengombinasikan ketegasan fase analisis kebutuhan standar IEEE 830 (Software Requirements Specification) dengan fleksibilitas pengembangan modular berbasis komponen.

2.2 Framework Next.js 15 & React 19

Next.js 15 merupakan framework web modern berbasis React 19 yang mengadopsi paradigma App Router. Next.js memungkinkan eksekusi komponen di sisi server (React Server Components) yang menghasilkan pemuatan halaman berkecepatan tinggi, optimasi SEO unggul, dan pemisahan tegas antara Server Actions/Route Handlers dengan Client Components.

2.3 TypeScript

TypeScript adalah bahasa pemrograman tingkat tinggi berbasis JavaScript yang menambahkan sistem pengetikan statis (static type-checking). Penggunaan TypeScript menjamin keamanan kode (*type-safety*), meminimalkan galat saat proses kompilasi (*compile-time error detection*), dan mempermudah pemeliharaan sistem skala besar.

2.4 Basis Data MySQL & TiDB Cloud Serverless

MySQL merupakan sistem manajemen basis data relasional (RDBMS) berbasis Structured Query Language. Dalam proyek ini, database di-host pada TiDB Cloud Serverless yang kompatibel penuh dengan protokol MySQL 8.0, menawarkan skalabilitas otomatis elastis, latensi rendah, serta koneksi terenkripsi TLS/SSL standar industri.

2.5 Prisma Object-Relational Mapping (ORM)

Prisma ORM adalah alat pemetaan objek relasional generasi baru untuk Node.js dan TypeScript. Prisma mengotomatisasi migrasi skema melalui berkas schema.prisma, menyediakan Prisma Client yang *type-safe*, serta secara otomatis menggunakan *parameterized queries* (prepared statements) untuk mengeliminasi kerentanan serangan SQL Injection secara mutlak.

2.6 Geographic Information System (GIS) & Leaflet.js

GIS adalah sistem komputer untuk menangkap, menyimpan, dan menampilkan data yang terkait dengan posisi di permukaan bumi. Pustaka Leaflet.js digunakan sebagai mesin pemetaan ringan berbasis vektor yang memetakan batas koordinat poligon petak sawah Desa Cirebon Girang di atas ubin peta satelit OpenStreetMap/Esri secara interaktif.

2.7 Artificial Intelligence & Google Gemini API

Kecerdasan Artifisial dalam sistem ini diwujudkan melalui integrasi Large Language Model (LLM) Google Gemini 3.0 Flash melalui Google AI Studio SDK. Model ini memiliki kapabilitas pemahaman konteks semantik bahasa alami yang tinggi dengan latensi pemrosesan rendah.

2.8 Retrieval-Augmented Generation (RAG) & Super Engine Agronomi

RAG adalah metode arsitektur di mana model bahasa diinjeksi dengan data eksternal sebelum menghasilkan respons. SI PADI menerapkan Hybrid RAG: data agregat terkini dari MySQL diambil secara asinkron lalu disuntikkan ke dalam System Instruction model AI. Selain itu, sistem diperkuat oleh Super Engine Agronomi Lokal yang menegakkan aturan semantik deterministik (latensi 0 ms) untuk memastikan kata tanya kuantitatif dan subjek dijawab secara akurat tanpa halusinasi.

2.9 Early Warning System & Gateway Notifikasi

Early Warning System (EWS) adalah mekanisme pendeteksian dan penyebaran informasi darurat kepada pihak berkepentingan sebelum dampak risiko terjadi. Sistem mengintegrasikan API Fonnte WhatsApp Gateway dan protokol SMTP Nodemailer untuk mendistribusikan notifikasi jadwal pemupukan HST serta verifikasi kode OTP 6 digit secara simultan ke ponsel pengguna.

2.10 Pengujian Perangkat Lunak & CI/CD DevOps

Pengujian perangkat lunak dilakukan untuk memastikan sistem bebas cacat (*bug-free*) dan memenuhi spesifikasi. Proyek ini mengimplementasikan Node.js Native Test Runner untuk pengujian unit otomatis, Black Box Testing untuk pengujian fungsionalitas antarmuka, serta GitHub Actions CI/CD Pipeline yang menjalankan validasi otomatis pada setiap commit kode.

3.3 Arsitektur Sistem 3-Tier

Sistem Informasi Pertanian Padi Desa Cirebon Girang mengadopsi pola arsitektur perangkat lunak Three-Tier Architecture:

  1. Presentation Tier (Client): Komponen antarmuka pengguna interaktif yang dibangun menggunakan React 19, Tailwind CSS, Lucide Icons, dan Leaflet GIS.
  2. Application / Logic Tier (Server): Next.js 15 App Router yang mengelola API Route Handlers, middleware keamanan autentikasi JWT, logika agronomis perhitungan HST, dan orchestrator AI Service.
  3. Data & Integration Tier: MySQL Serverless di TiDB Cloud yang diakses type-safe via Prisma ORM, terhubung ke layanan eksternal Google Gemini API, Fonnte WhatsApp Gateway, dan SMTP Server.

3.4.3 Class Diagram Berprinsip SOLID

Perancangan berorientasi objek pada sistem ini menerapkan 5 prinsip SOLID secara konsisten pada arsitektur Service Layer:

  • Single Responsibility Principle (SRP): Memisahkan AuthService (hanya menangani JWT dan enkripsi sandi), AiService (hanya memproses bahasa alami dan injeksi konteks), dan NotificationService (hanya menyalurkan pesan gateway).
  • Open-Closed Principle (OCP): Mendefinisikan antarmuka abstrak IAiProvider sehingga provider AI baru dapat ditambahkan tanpa memodifikasi kode inti pemanggil.
  • Liskov Substitution Principle (LSP): Implementasi GeminiChatProvider dan LocalAgronomyProvider dapat saling menggantikan peran secara transparan.
  • Interface Segregation Principle (ISP): Memisahkan antarmuka pengiriman IWhatsAppGateway dan IEmailSender secara independen.
  • Dependency Inversion Principle (DIP): Modul Route Handler bergantung pada abstraksi interface layanan, bukan pada implementasi pustaka konkret secara langsung.

3.4.4 Sequence Diagram

Sequence Diagram menggambarkan alur pertukaran pesan asinkron antara antarmuka React Client, Next.js API Handler, Prisma ORM, TiDB Cloud Database, dan Google Gemini API. Ketika kueri seperti "berapa total pengguna" dikirimkan, route handler memanggil aiService.ts untuk mengambil agregasi data pengguna dari database via Prisma, memformat jawaban angka secara deterministik, dan mengembalikannya ke client dalam hitungan milidetik.
