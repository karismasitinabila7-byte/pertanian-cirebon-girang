BAB I: INISIASI & PENYUSUNAN PRD / SRS MANDIRI (IEEE 830)

1.1 Latar Belakang Masalah Riil Desa Cirebon Girang

Desa Cirebon Girang yang terletak di Kecamatan Talun, Kabupaten Cirebon, Jawa Barat, memiliki luas hamparan sawah produktif sebesar 6,00 Hektar (60.000 m²) yang terbagi ke dalam 4 petak lahan utama pada 3 blok dusun: Blok Manis (Dusun Karang Anyar), Blok Wage (Dusun Girang Hilir), dan Blok Pahing (Dusun Cirebon Ilir). Sektor pertanian padi sawah ini dinaungi oleh 3 Kelompok Tani (Poktan) binaan desa, yaitu Poktan Sri Rejeki (Ketua: Bapak Sukardi), Poktan Sumber Subur (Ketua: Bapak H. Karyono), dan Poktan Tani Makmur (Ketua: Bapak Sutarjo).

Berdasarkan hasil observasi lapangan dan wawancara mendalam bersama Kepala Desa (Kuwu) Desa Cirebon Girang, Bapak Karsiman, S.Sos, teridentifikasi sejumlah kendala mendasar pada tata kelola budidaya padi konvensional yang sedang berjalan:

  • Pencatatan Fisik Rentan Tercecer: Pendataan inventarisasi luas petak, kepemilikan lahan, dan data anggota petani masih dicatat manual dalam buku register desa, sehingga memicu inkonsistensi data batas sawah antar-petani.
  • Keterlambatan Jadwal Pemupukan (Fase HST): Petani kerap mengalami kesulitan dalam menghitung umur tanaman secara presisi berbasis Hari Setelah Tanam (HST). Akibatnya, pemupukan susulan I (10–14 HST) dan susulan II (30–35 HST) terlambat diaplikasikan, menyebabkan penurunan anakan produktif dan potensi malai hampa.
  • Absennya Sistem Peringatan Dini (Early Warning System): Perubahan anomali cuaca lokal (kelembapan tinggi dan curah hujan ekstrem) serta ancaman ledakan hama wereng batang coklat (WBC) dan blas leher sering terlambat dimitigasi karena tidak adanya saluran komunikasi darurat yang terhubung langsung ke WhatsApp petani.
  • Sulitnya Konsultasi Agronomi Berbasis Data: Petani membutuhkan konsultasi agronomis instan mengenai takaran pupuk berimbang dan diagnosis penyakit tanpa harus menunggu kedatangan Penyuluh Pertanian Lapangan (PPL).
  • Birokrasi Pelaporan Kedinasan: Perangkat desa membutuhkan rekapitulasi realisasi panen dan luas baku lahan yang cepat untuk dilaporkan secara resmi ke Dinas Pertanian Kabupaten Cirebon.

Guna mentransformasikan permasalahan di atas menjadi solusi komputasional terukur, dibangunlah platform SI PADI (Sistem Informasi Pertanian & Manajemen Budidaya Padi Desa Cirebon Girang). Value Proposition utama platform ini mencakup:

Nilai Strategis Platform SI PADI:
1. Spatial Precision: Digitalisasi batas petak sawah berbasis Geographic Information System (Leaflet GIS) dengan koordinat poligon satelit interaktif.
2. Automated Agro-Intelligence: Perhitungan otomatis Hari Setelah Tanam (HST) dan penyaluran notifikasi darurat Early Warning System multi-saluran via WhatsApp Gateway (Fonnte) dan Email SMTP.

4. Certified Official Reporting: Pembuatan otomatis lembar laporan resmi ber-Kop Kantor Kuwu bertanda tangan sah Kuwu Bapak Karsiman, S.Sos.

1.5 Spesifikasi Kebutuhan Non-Fungsional (NFR)

  • NFR-01 (Kinerja & Kecepatan Respon): Waktu render halaman awal (First Contentful Paint) berada di bawah 1.5 detik. Respon mesin pencocokan AI lokal berlatensi 0 ms, sedangkan pemanggilan model Gemini Cloud berlatensi < 3.0 detik.
  • NFR-02 (Keamanan Siber): Seluruh password dienkripsi satu arah dengan bcryptjs (salt 10). Token sesi JWT disimpan di HttpOnly, SameSite=Lax, Secure cookie. Akses database diproteksi oleh Prisma ORM menggunakan Parameterized Queries untuk memitigasi serangan SQL Injection secara tuntas. Output HTML disanitasi otomatis oleh React 19 untuk memitigasi Cross-Site Scripting (XSS).
  • NFR-03 (Skalabilitas & Ketersediaan): Basis data di-host pada TiDB Cloud Serverless MySQL dengan arsitektur multi-AZ auto-scaling. Aplikasi web di-deploy pada infrastruktur global edge Vercel dengan garansi uptime 99.9%.
  • NFR-04 (Kompatibilitas & Responsivitas Mobile-First): Antarmuka web dibangun menggunakan Tailwind CSS yang responsif pada resolusi layar ponsel pintar (360px) hingga monitor desktop ultra-wide (1920px).

1.6 Spesifikasi Fitur AI Utama (Hybrid RAG & Deterministic Super Engine)

Fitur Kecerdasan Artifisial pada SI PADI mengimplementasikan paradigma Hybrid Retrieval-Augmented Generation (RAG) yang menggabungkan:

  1. Dynamic Real-Time Context Injection: Backend Next.js secara dinamis mengkueri basis data MySQL TiDB Cloud untuk mengambil agregat termutakhir (jumlah pengguna, rincian petani, kelompok tani, luas petak lahan, siklus musim tanam, hasil panen, dan peringatan aktif). Seluruh data terstruktur ini disuntikkan langsung ke dalam System Instruction LLM Cloud (Google Gemini 3.0 Flash / OpenAI GPT-4o-mini) sehingga AI tidak pernah mengalami halusinasi data desa.
  2. Deterministic Super Engine Agronomi Lokal: Sistem dilengkapi mesin lokal berbasis aturan heuristik cerdas yang menguasai seluruh inventarisasi desa dan modul teknis Kementan RI. Jika API key belum terpasang atau kuota cloud habis, mesin lokal ini langsung melayani pengguna secara instan (0 ms latensi) tanpa penurunan kualitas informasi.
  3. Strict Clue Evaluation: Dilengkapi parser semantik yang menegakkan aturan:
    • Kata tanya "BERAPA" → Dijawab ringkas dengan angka statistik (contoh: "Total pengguna terdaftar adalah 6 orang").
    • Kata tanya "SIAPA" → Dijawab langsung dengan nama subjek spesifik (contoh: "Kepala Desa (Kuwu) adalah Bapak Karsiman, S.Sos").

BAB II: PERANCANGAN UML & ARSITEKTUR SISTEM MANDIRI (SDD)

2.1 Arsitektur Tingkat Tinggi Perangkat Lunak (Layered Architecture)

Sistem Informasi Pertanian Padi Desa Cirebon Girang dirancang menggunakan pola Layered Architecture yang memisahkan tanggung jawab antarmuka pengguna, logika bisnis, dan persistensi data:

  • Presentation Layer: Dibangun menggunakan Next.js 15 App Router, React 19, Tailwind CSS, Lucide React Icons, dan Leaflet.js untuk visualisasi pemetaan spasial petak sawah.
  • Application & Domain Service Layer: Berisi modularisasi logika bisnis murni yang mematuhi prinsip SOLID: AuthService, AiService, NotificationService, AgronomyEngine, dan ReportService.
  • Persistence Layer: Menggunakan Prisma ORM Client sebagai layer perantara abstraksi basis data yang type-safe.
  • Database & Infrastructure Layer: TiDB Cloud Serverless MySQL 8.0, Vercel Serverless Edge, Google Gemini API, Fonnte WhatsApp Gateway API, dan Nodemailer SMTP.

2.4 Pemodelan Class Diagram Berorientasi Objek (Mematuhi Prinsip SOLID)

Struktur kode pada backend mengimplementasikan prinsip SOLID (Single Responsibility, Open-Closed, Liskov Substitution, Interface Segregation, Dependency Inversion):

  • Single Responsibility Principle (SRP): Setiap modul service hanya memiliki satu alasan untuk berubah. AuthService hanya mengurusi otentikasi JWT/Bcrypt, AiService mengurusi pemrosesan NLP & Context Injection, dan NotificationService mengurusi dispatching pesan.
  • Open-Closed Principle (OCP): Arsitektur penyedia AI berbasis antarmuka IAiChatProvider yang dapat diperluas untuk vendor baru (DeepSeek, Claude, dll.) tanpa memodifikasi kode inti pemanggil.
  • Liskov Substitution Principle (LSP): GeminiChatProvider, OpenAiChatProvider, dan LocalAgronomyProvider dapat saling menggantikan secara mulus tanpa menimbulkan kegagalan alur percakapan.
  • Interface Segregation Principle (ISP): Antarmuka notifikasi dipisah menjadi IWhatsAppService dan IEmailService agar kelas pemanggil tidak dipaksa mengimplementasikan protokol yang tidak dibutuhkan.
  • Dependency Inversion Principle (DIP): Modul tingkat tinggi (Route Handler) bergantung pada abstraksi interface service, bukan implementasi konkret library pihak ketiga.

3.3 Mekanisme Keamanan Siber Web (Anti-SQLi, Anti-XSS, Anti-CSRF, Bcrypt)

  • Pencegahan SQL Injection: Seluruh kueri basis data menggunakan Prisma ORM Client yang secara otomatis mengompilasi input pengguna menjadi Prepared Statements / Parameterized Queries, sehingga input berbahaya tidak dapat memanipulasi struktur perintah SQL.
  • Pencegahan Cross-Site Scripting (XSS): Framework React 19 secara native melakukan sanitasi dan konversi HTML entity encoding pada setiap variabel yang dirender ke DOM.
  • Pencegahan Cross-Site Request Forgery (CSRF): Token sesi disimpan dalam cookie bertanda HttpOnly, SameSite=Lax, dan Secure pada protokol HTTPS Vercel, mencegah pembacaan token dari JavaScript pihak ketiga.
  • Perlindungan Kredensial: Password dienkripsi dengan algoritma bcryptjs 10 salt rounds sebelum disimpan ke database TiDB Cloud.

3.4 Early Warning System & Integrasi WhatsApp Gateway Fonnte

Peringatan dini dievaluasi otomatis oleh server berdasarkan kalkulasi Hari Setelah Tanam (HST) dan anomali kelembapan/cuaca API Open-Meteo. Notifikasi dipancarkan langsung ke ponsel petani melalui WhatsApp Gateway API (Fonnte):
