"Proyek ini saya angkat dari studi kasus nyata di Desa Cirebon Girang, Kecamatan Talun, Kabupaten Cirebon. Desa ini memiliki hamparan sawah produktif seluas 6,00 Hektar yang dinaungi oleh 3 Kelompok Tani binaan, yaitu Poktan Sri Rejeki, Sumber Subur, dan Tani Makmur. Berdasarkan observasi dan wawancara bersama Kuwu Desa Cirebon Girang, Bapak Karsiman, S.Sos, saya mengidentifikasi 3 masalah kritis: Pertama, pendataan lahan sawah dan anggota petani masih dicatat manual dalam buku register desa, sehingga rawan tercecer dan memicu ketidakpastian batas petak. Sebagai solusinya, SI PADI hadir dengan Value Proposition utama: mendigitalisasi batas spasial petak sawah berbasis GIS, mengotomatisasi peringatan dini pemupukan multi-saluran ke WhatsApp dan Email, serta menghadirkan Asisten Cerdas AI yang membaca data riil desa untuk konsultasi budidaya."

Sedangkan dari sisi Non-Fungsional (NFR), sistem dirancang memiliki waktu muat halaman di bawah 1,5 detik, keamanan kata sandi bcryptjs salt 10, database MySQL di TiDB Cloud Serverless yang kebal SQL Injection via Prisma ORM, serta antarmuka responsif mobile-first menggunakan Tailwind CSS."

Segmen 4: Bedah Class Diagram & Kepatuhan Prinsip SOLID 03:00 – 04:15
Visual: Menampilkan Class Diagram berorientasi objek dengan interface dan inheritance.
"Beralih ke Class Diagram, perancangan sistem berorientasi objek ini secara ketat mematuhi 5 prinsip SOLID: 1. Single Responsibility Principle (SRP): Saya memisahkan kelas domain secara tegas. AuthService hanya bertanggung jawab atas enkripsi dan token JWT, AiService hanya menangani pemrosesan bahasa dan context injection, dan NotificationService hanya mengurusi pengiriman pesan. 2. Open-Closed Principle (OCP): Saya membuat antarmuka abstrak IAiProvider. Jika di masa mendatang ingin menambahkan vendor AI baru seperti DeepSeek atau Claude, kita cukup mengimplementasikan antarmuka ini tanpa mengubah kode modul pemanggil. 3. Liskov Substitution Principle (LSP): Kelas konkret GeminiChatProvider dan LocalAgronomyProvider dapat saling menggantikan peran tanpa menimbulkan error pada controller. 4. Interface Segregation Principle (ISP): Antarmuka notifikasi dipisah menjadi IWhatsAppGateway dan IEmailSender agar tidak ada kelas yang dipaksa mengimplementasikan metode yang tidak relevan. 5. Dependency Inversion Principle (DIP): Controller dan Route Handler bergantung pada kontrak abstraksi antarmuka service, bukan pada implementasi library konkret."
Segmen 5: Bedah Sequence Diagram & Alur Pertukaran Pesan 04:15 – 05:15
Visual: Menampilkan Sequence Diagram alur pertukaran pesan Client-Server-DB-AI.
"Pada Sequence Diagram, kita dapat melihat pertukaran pesan secara kronologis: Ketika pengguna di sisi Client mengirimkan kueri seperti 'berapa total pengguna', payload dikirim melalui HTTP POST ke /api/ai/chat. Route handler meneruskannya ke fungsi processAiChat pada aiService.ts. Service layer melakukan kueri ke basis data MySQL TiDB Cloud melalui Prisma ORM untuk mengambil data agregat terkini. Parser semantik mendeteksi fungsi isBerapaQuery() bernilai TRUE, sehingga sistem langsung memformat jawaban angka ringkas tanpa membocorkan kredensial pribadi. Respon JSON kemudian dikembalikan ke komponen antarmuka pengguna dalam hitungan milidetik secara asinkron."
