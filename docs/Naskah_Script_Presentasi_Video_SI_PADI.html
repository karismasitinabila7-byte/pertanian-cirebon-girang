BAGIAN 2: LATAR BELAKANG INOVASI & KONSEP PERCONTOHAN DESA CIREBON GIRANG [01:15 – 02:45]
🖥️ Tampilan Layar: Slide Latar Belakang / Peta Desa Cirebon Girang / Diagram Konsep Inovasi Aplikasi.
"Bapak Dosen dan rekan-rekan sekalian, mengapa saya memilih Desa Cirebon Girang, Kecamatan Talun, Kabupaten Cirebon sebagai objek percontohan dalam rancang bangun web percobaan ini?
Desa Cirebon Girang memiliki potensi agraris yang sangat strategis dengan hamparan sawah produktif seluas 6,00 Hektar dan 3 Kelompok Tani binaan, yaitu Poktan Sri Rejeki, Poktan Sumber Subur, dan Poktan Tani Makmur.
Melalui analisis kebutuhan umum pada tata kelola pertanian pedesaan, saya melihat beberapa kendala mendasar yang sering dialami di lapangan:
Pertama, Pencatatan Konvensional: Pendataan batas petak sawah dan keanggotaan kelompok tani pada umumnya masih manual, sehingga rawan tercecer dan batas lahan belum terpetakan secara digital.
Kedua, Tantangan Jadwal Pemupukan: Petani sering kali mengandalkan perkiraan manual dalam menghitung umur tanaman berbasis Hari Setelah Tanam (HST). Akibatnya, pemupukan susulan berisiko terlambat diaplikasikan.
Ketiga, Penyampaian Peringatan Dini: Belum adanya saluran informasi otomatis yang langsung mengirimkan peringatan hama atau anomali cuaca ke ponsel petani.
Berangkat dari latar belakang tersebut, saya berinisiatif membangun web percobaan SI PADI ini sebagai solusi teknologi terpadu: mendigitalisasi batas sawah dengan peta GIS satelit interaktif, mengotomatiskan peringatan pemupukan ke WhatsApp dan Email, serta menghadirkan Asisten AI cerdas untuk membantu konsultasi pertanian berbasis data riil desa.
Besar harapan saya, jika web percobaan ini nantinya terpakai di desa tersebut, proses bertani dan pelaporan hasil panen dapat menjadi jauh lebih mudah, terstruktur, dan modern."
BAGIAN 3: SPESIFIKASI KEBUTUHAN SISTEM (PRD / SRS STANDAR IEEE 830) [02:45 – 04:15]
🖥️ Tampilan Layar: Dokumen Laporan Bab II (Tabel FR-01 s/d FR-08, NFR, dan 3 User Persona).
"Untuk memastikan web percobaan ini terstruktur sesuai kaidah rekayasa perangkat lunak, saya menyusun dokumen Product Requirements Document (PRD) mengacu pada standar IEEE 830.
Sistem dirancang dengan arsitektur Role-Based Access Control (RBAC) yang membagi hak akses ke dalam 3 Persona Pengguna:
1. Administrator, memiliki 12 modul menu untuk mengelola master data pengguna, konfigurasi AI, dan audit sistem.
2. Perangkat Desa (Kuwu), memiliki 10 modul menu untuk monitoring statistik luas lahan per dusun, rekapitulasi panen, dan penerbitan surat dinas resmi.
3. Petani, memiliki 10 modul menu praktis untuk pendaftaran mandiri, memantau jadwal HST sawahnya, mencatat kegiatan budidaya, dan berkonsultasi budidaya.
Adapun Kebutuhan Fungsional kunci yang saya rancang meliputi:
- FR-01: Autentikasi Stateless JWT dengan proteksi HttpOnly Cookie.
- FR-02: Registrasi Mandiri Petani dengan simulasi verifikasi OTP 6 digit yang dikirim simultan via WhatsApp Gateway Fonnte dan Email SMTP dengan masa kedaluwarsa 5 menit.
- FR-04: Pemetaan spasial GIS batas sawah interaktif berbasis Leaflet.js.
- FR-05 & FR-06: Manajemen musim tanam otomatis dengan kalkulasi dosis pemupukan berimbang berbasis umur tanaman.
- FR-08: Ekspor format dokumen kedinasan resmi ber-Kop Surat Kantor Kuwu.
Sedangkan Kebutuhan Non-Fungsional (NFR) difokuskan pada kecepatan akses di bawah 1,5 detik, keamanan kata sandi bcrypt salt 10, basis data MySQL Serverless di TiDB Cloud yang kebal SQL Injection, serta desain antarmuka mobile-first."
BAGIAN 4: PERANCANGAN SISTEM (SDD), 4 DIAGRAM UML, & PRINSIP SOLID [04:15 – 06:15]
🖥️ Tampilan Layar: Dokumen Bab III (Gambar Use Case, Activity, Class SOLID, dan Sequence Diagram).
"Pada tahap perancangan sistem atau Software Design Description (SDD), saya memodelkan alur logika perangkat lunak ke dalam 4 Diagram UML Utama:
1. Use Case Diagram: Memetakan interaksi 3 Aktor yaitu Administrator, Perangkat Desa, dan Petani, serta integrasi 2 sistem eksternal yaitu WhatsApp Gateway dan Google Gemini AI. Terdapat 14 use case terdefinisi yang mencakup alur sistem dari autentikasi hingga penerbitan laporan.
2. Activity Diagram: Memodelkan dua aktivitas utama: pertama, alur registrasi OTP petani dari pengisian data, pembangkitan kode acak, penyaluran pesan via gateway, hingga aktivasi akun. Kedua, alur pemrosesan AI di mana input pertanyaan dinormalisasi, disaring lewat mesin agronom lokal, dan disuntikkan ke model AI cloud.
3. Class Diagram & Kepatuhan Prinsip SOLID: Dalam desain berorientasi objek, saya menerapkan 5 prinsip SOLID secara disiplin: Single Responsibility memisahkan AuthService, AiService, dan NotificationService; Open-Closed menggunakan antarmuka abstrak IAiProvider; Liskov Substitution memastikan Gemini provider dan local provider dapat saling menggantikan; Interface Segregation memisahkan antarmuka WA dan Email; dan Dependency Inversion memastikan controller bergantung pada abstraksi interface layanan.
4. Sequence Diagram: Memvisualisasikan pertukaran pesan asinkron HTTP POST dari antarmuka React Client ke Next.js Route Handler, pemanggilan Prisma ORM ke basis data, hingga pengembalian respons JSON dalam hitungan milidetik."
BAGIAN 5: PERANCANGAN BASIS DATA (ERD 13 TABEL RELASIONAL) & TECH STACK [06:15 – 07:45]
🖥️ Tampilan Layar: Diagram ERD 13 Tabel Relasional di Bab III Laporan, lalu beralih ke slide Tech Stack.
"Untuk menjamin keutuhan dan persistensi data pada web percobaan ini, saya merancang Entity Relationship Diagram (ERD) yang terdiri dari 13 Tabel Relasional ternormalisasi hingga 3NF:
Mulai dari tabel users, farmers, farmer_groups, farm_lands, planting_seasons, cultivation_activities, harvest_records, ai_consultation_logs, otp_verifications, early_warnings, fertilizer_schedules, system_configs, hingga audit_logs.
Arsitektur teknologi yang saya bangun mengadopsi standar modern:
- Framework Utama: Next.js 15 App Router dengan React 19 dan TypeScript untuk keamanan kode pengetikan.
- Desain Tampilan: Tailwind CSS dengan tema Emerald Agrikultur yang bersih dan mudah digunakan.
- Basis Data: MySQL 8.0 yang berjalan di TiDB Cloud Serverless dengan koneksi terenkripsi SSL.
- ORM: Prisma ORM untuk menjamin query type-safe dan kebal serangan SQL Injection.
- Keamanan Sesi: Stateless JSON Web Token (JWT) yang disimpan di HttpOnly Cookie dan enkripsi kata sandi Bcrypt 10 salt.
- Integrasi Layanan: Leaflet GIS, Google Gemini 3.0 Flash API, Fonnte WhatsApp API, dan Nodemailer SMTP."
